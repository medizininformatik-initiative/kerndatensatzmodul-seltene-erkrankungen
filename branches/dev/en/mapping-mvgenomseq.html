Mapping Genome Sequencing Model Project (KDK)

  • Basis and direction
  • Scope
  • Mapping
  • KDK fields without a source in this module
  • Maintenance

In the genome sequencing model project under § 64e SGB V (Modellvorhaben Genomsequenzierung), participating providers submit a clinical data set (KDK, Klinischer Datenkranz) for each case to BfArM. For rare diseases this is the RareDiseases submission. In a data integration centre, much of it already exists in the profiles of this module. This page shows where.

Basis and direction

  • Target: BfArM schema MVGenomseq_KDK v2.3, parts RareDiseasesCase, RareDiseasesPlan and RareDiseasesFollowUp. Its structure is the logical model mii-lm-seltene-mvgenomseq, with field names unchanged from the JSON schema.
  • Direction: from a profile of this module to a KDK field, i.e. the ETL path of a data integration centre that builds a submission from its FHIR data. Machine-readable in the ConceptMap mii-cm-seltene-to-mvgenomseq.
  • Codes: the therapy recommendations carry the MVGenomSeq categories as slices of their own, but with this module's codes (gene-therapy, early-detection). The translation into the KDK values (genetic, earlyDetection) is mii-cm-seltene-therapieempfehlung-to-mvgenomseq.
  • Reverse direction: importing a KDK submission into a data integration centre (KDK → MII) is maintained as an executable StructureMap by the community project MVGenomSeq-on-FHIR. It is still a draft there.

Scope

As in the Oncology module, the mapping covers only what this module carries:

  • metaData (submission, declaration of participation, insurance, birth date, residence) belongs to the Person and Consent modules.
  • molecular (variants) belongs to the Molecular Genetics Report module; its gaps are in HDB-976.

Mapping

The Relationship column gives the ConceptMap equivalence. Derived means the KDK value is computed from the source element by the rule in the note, not copied. Notes are in German, as in the ConceptMap; the KDK is a German national data set.

Coverage: 33 of 50 KDK fields have a source in this module, including 14 of the 18 required ones (required once the section is submitted). The rest: 11 in other modules, 6 gaps in the MII core data set, 0 open.

Maintenance

When BfArM changes the schema, three steps are needed: update the logical model, review the ConceptMap and run scripts/generate-mvgenomseq-mapping.py. A new KDK field without a source then shows up as not yet assessed until it is categorised in the script's gap list.
