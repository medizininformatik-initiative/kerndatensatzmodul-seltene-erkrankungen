# Migration report — Seltene Erkrankungen → MII KDS module template

## How to use this report

This report is written for someone who has **never seen** the migration skill, this repository's history, or the tooling. Every code is explained where it is used; a backstop glossary is at the end.

Read *Summary* first. Then work the three queues in order:

| Queue | What it is | Who acts | If nobody acts |
| --- | --- | --- | --- |
| **① Decision** | Open questions only a human can answer (identity, licence, version pins) | Module maintainer + TF-KDS (Gate A) | The guide ships with an undeclared licence and unreviewed pins |
| **② Review** | Text the migration *wrote* or *machine-translated*, and routing decisions | The module's clinical/technical authors (Gates B, C) | Unreviewed English text and derived passages reach readers as if they were authored |
| **③ QA triage** | What the build reports, and whose problem each item is | Whoever owns the underlying artefact | Pre-existing source defects get attributed to this migration |

**Nothing here is published.** Merging this PR renders a *preview* on GitHub Pages; a release is a separate, human decision (Gate D, KDS governance).

## Summary — read this first (for everyone)

The MII KDS module **Seltene Erkrankungen** (rare diseases) has been moved off Simplifier onto the MII KDS module template (`mii-kds-module-template` v0.11.3). What that means in practice: the guide is now built by the HL7 FHIR IG Publisher from sources in this repository, it renders in **two languages** (English as the default, German as the translation), and every page and artefact is generated by a reproducible build instead of by the Simplifier platform.

**The module's identity is unchanged.** Its canonical URL, package id, resource ids and profile URLs are exactly what they were — nothing that a consumer depends on has moved. The one deliberate change is the **version: 2026.0.1 → 2027.0.0-ballot**, decided by the module maintainer on 2026-08-28 (the same target the Bildgebung module used).

**All 163 artefacts came across.** The before/after measurement (`prepost-delta.tsv`) compares 33 properties: 27 unchanged, 1 improved, 4 expected changes, and exactly 1 "regression" — which is the intended version bump the analyzer cannot know about. Profile, extension, ValueSet, CodeSystem, CapabilityStatement and example counts are identical on both sides.

**The narrative was preserved and measured, not assumed.** 1030 text runs from all 41 source pages were checked against the migrated German pages: **986 found (95.7 %)**. Every one of the 44 exceptions is classified and explained in ③ — none is unexplained content loss.

**Two things the migration recovered that the previous state had lost:** the PlantUML timeline diagrams for both case examples (Marfan, SMA) existed only as `*(Diagramm folgt.)*` placeholders in the ported content; their sources were extracted from the Simplifier tree, rendered, and embedded in both languages.

**What still needs people:** the module **declares no licence anywhere** — not in `sushi-config.yaml`, not in `package.json`, not as a LICENSE file (the artefact level uses CC-BY-4.0 via a RuleSet). The migration deliberately did **not** invent one. Six floating dependency pins (`2026.0.x`, `1.5.x`) were resolved to concrete registry versions because the template's convention check rejects floating versions. And every English page is a **machine translation marked `TODO:REVIEW`** — the source is German-only, and the template's default language is English, so English pages had to be produced. All of this is in queues ① and ②.

**Build status:** SUSHI 0 errors / 0 warnings. IG Publisher exits 0 and renders both language trees (804 pages each). QA reports 116 errors — every one of them classified in ③, and every one either a terminology-server false positive or a defect the source already had. The one defect the migration itself introduced (a wrong link on the German implementer-guidance page) was found by the verification pass and fixed.

## Codes, gates and words used in this report

**Gates** are the four mandatory human review points. **A** = identity (module maintainer + TF-KDS), **B** = narrative (the module's authors), **C** = language/translation, **D** = release per KDS governance (TF KDS / AG IOP / NSG) — nothing publishes before D.

**Check codes** come from the verification script. `C1`/`C2` artefact conservation and reachability · `C3` page-set coverage · `C4` source text present somewhere · `C5` menus and page reachability · `C6` text landed where the map promised · `C7` rewritten text carries a marker · `F1`–`F3` identity, dependency pins, licence · `P1`–`P5` toolchain and template provenance · `R1`–`R5` rendering and language parity · `L0`–`L4` the run log read back as a second oracle.

**Three verdicts, not two:** `IDENTISCH` (passes), `DIVERGIERT` (a named difference with evidence), `NICHT PRÜFBAR` (could not be mechanised — **this is not a pass**; a human owes each one an answer).

**`TODO:REVIEW`** marks migrated content a human must read. **DERIVED marker** = an HTML comment plus a visible blue box marking text the migration *wrote* rather than moved.

**Source shape A** = the source was already a SUSHI/IG-Publisher project (it was), so the FSH was transferred in place rather than derived with goFSH.

## Mini-glossary

**Canonical URL** — the module's permanent identifier namespace; changing it breaks every consumer, which is why guardrail 1 forbids it. **CalVer** — MII modules version as `YYYY.n.n`, not SemVer. **CRMI** — the HL7 Canonical Resource Management Infrastructure IG, whose claims the template's IG resource makes. **FQL** — Simplifier's Firely Query Language, used to generate tables in the old guide; the IG Publisher generates those views itself. **Intro note** — a Markdown file rendered on top of an artefact's generated page. **M9 / M11** — the template's rules for optional pages and for the security & privacy section. **Shape A** — a source that was already a SUSHI project. **THO** — HL7 Terminology, the code system package.
